# ── Pickle-compatibility pins ────────────────────────────────────────────
# The committed model artifacts under ml/**/saved_models/ are binaries, not
# retrained at deploy time, and they embed the exact library versions that
# serialised them (scikit-learn 1.8.0 / numpy 2.4.x). The serving environment
# must therefore match the training environment.
#
# With the previous unbounded `scikit-learn>=1.3`, the deployed image resolved
# a different version and unpickling the six GradientBoosting models failed
# with "No module named '_loss'" -- they reference sklearn._loss.link and
# sklearn._loss.loss, which only resolve under the version that wrote them.
# Symptom: every advisor request returned "Analysis Interrupted".
#
# numpy is held to the 2.x line for the same reason: a numpy-2 pickle cannot
# be read by numpy 1.x. Re-pin these together whenever the models are retrained.
